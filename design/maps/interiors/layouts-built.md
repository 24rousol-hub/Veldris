## What the author does next

1. **Close Porymap** (or reload it after) so it does not overwrite `layouts.json`.
2. For each building: Porymap, Layouts tab, right-click the layout, **Add New Map with Layout**; name the map as the card does (for example `Smeltham_Canteen`). Several buildings can share one layout; painting in one changes all of them.
3. Place the exit warp on the mat (listed per layout below), objects and signs (the `npc` tiles each builder reserved are in the module, and the 'Do in Porymap' lines say what to set), then move the new `.include "data/maps/<Name>/scripts.inc"` line into the Veldris block of `data/event_scripts.s` as the CLAUDE.md checklist says.
4. Metatile **behaviours** (fridge, stove, TV, counters, shelves) are the author's to set in Porymap; the lines below say which tiles already carry one.

## How it was checked

- `design/tools/interiors/layoutkit.py` lints every layout: array shape and type, every metatile id inside its tileset, only floor and solid collision/elevation classes, an exit mat on the bottom row with a walkable cell above it, every walkable tile reachable from the door (or listed as closed on purpose), every reserved object tile reachable, and the map-size limit. The only warnings left are the three upstairs doors (Apiary 2F, Archive, Lounge 2F) that sit on a side wall. Run `python3 install_layouts.py --check`.
- Each family was built by one agent, then **reviewed by a second agent that did not trust the first** (it re-ran the lint, looked at every picture, re-read the cards and reviewed the code), then fixed where it found a major problem (homes, shops, offices, halls and the Fairy gym were fixed once; houses and the other gyms passed). The gym modules also check their own puzzles at import (route exists, no soft-lock) and refuse to load if a check fails.
- `make -j4` passes with all 37 layouts installed.
- Reviewers are checking pictures against the cards, not playing: nothing here has been seen in the game yet.
